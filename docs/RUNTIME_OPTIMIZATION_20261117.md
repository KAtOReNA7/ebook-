## 接续边界

仍在原进程中的丢失 ACK：重新验证当前租约，读取完整目标范围，逐字段核对整批；只有整批已经成功才继续未发出的后续步骤。部分、缺失、冲突结果停止，不盲目重发。

进程已结束后，先运行 `python tools/inspect_interrupted_stage.py --export-evidence`。新受控入口 `python scripts/daily_run.py --run-kind scheduled --resume-interrupted` 目前只在**原 Windows 主机、原 checkout**能证明旧进程及采集子进程均已停止时自动续接；其他主机的活性不能仅凭超时推断。未知 guard 保持阻断。正常跨机接续已提交检查点不受此限制。全部业务阶段完成而仅最终共享提交失败时，只核对并补共享提交，不再运行来源或创建通知。

这不声称自动解决任意未知写入，也不等同于实体电脑断电验收。远端阶段尚未保存的本地完成标记不会作为成功依据。

## 格式转换

先执行 `python tools/migrate_evidence_store.py` 获取锁内预览；核实后 `--execute`。工具保留所有原文件字节，前后独立读取全部业务表及工作流，业务内容或通知状态变化均停止并保留保护。只转换私有状态存储，零业务写入、零通知。失败不删除保护或抢锁。

归档只读导出：`python tools/export_archived_evidence.py --path <相对路径> --sha256 <版本哈希>`。输出到新的私有 receipts 目录，不覆盖活动配置。

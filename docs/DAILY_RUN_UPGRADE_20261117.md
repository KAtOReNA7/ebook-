## 全部实施范围

1. **不可变证据复用（最高）**：原始响应按内容哈希保存和引用，阶段只上传新证据与变化清单。不得只靠文件存在、文件名、大小或mtime认定内容一致。完整原文、哈希、身份、实际观察时间及来源链须可跨机恢复。
2. **从具体失败步骤接续（最高）**：区分未发出写入、服务端成功但回执丢失、结果未知。先核验原租约、原执行存活情况、远端阶段、完整计划和实际业务回读；确证后才续接剩余步骤。成功来源不重采，已创建通知只核对状态，共享提交失败仅恢复提交。未知POST/PATCH不盲重试，不删guard、不超时抢锁。不能用一个成功请求冒充该步骤整体完成。
3. **合并轻量检查的重复保存（高）**：保存必要的外部写入前证据和恢复点；无外部写入的连续小检查可合并提交变化清单。保留因果顺序，失败不能推进业务或费用比较基线。不得用减少发布前独立回读换取性能。
4. **同次执行的作品采样复用（中）**：主微信与版权方模块对同一官方ID、同一指标口径复用本次有效成功响应。保留观察时间及原文引用；失败项单独补查，不能跨平台复制指标、跨日拿缓存冒充新观察或改变追踪起点。
5. **只读网络容错（中）**：GitHub锁归属等瞬时GET失败采用有上限的重试、退避、超时和分次证据。每次业务写入仍确认当前租约有效，不能缓存过期所有权放行。鉴权/权限/业务错误不得当瞬时错误无限重试。
6. **自动性能报告**：每次运行自动输出采集、业务同步、共享恢复/保存、比较、独立回读、通知、最终提交的墙钟时间、CLI调用数、重试数及数据量。区分整轮墙钟与重叠阶段/调用时间之和；CLI调用数不是HTTP次数。失败/恢复时间单列但不从总时间剔除。
7. **历史证据分层**：以业务比较、追踪和恢复的引用图划分活动数据与历史归档，避免历史原文每日重传。原始证据不擅自删除；新电脑能够按引用取回、校验完整原字节。归档不可访问或哈希错误必须阻断，不可静默缺省。优先复用现有私有存储，不把未验证的新服务迁移混入此次升级。

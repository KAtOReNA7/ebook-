# 日常查看与运营分析

## 常用入口

日常主要用三个入口：运营趋势看板选作品看变化、项目总表看最新情况、营销服务明细查投放。其余表用于查看原始每日数据或核对采集结果。

| 表／入口 | 内容 | 什么时候看 |
| --- | --- | --- |
| 运营趋势看板 | 微信今日阅读、点评人数、推荐值；番茄累计阅读、点评人数、书评数量 | 看所选日期内单书变化、多书对比 |
| 项目总表 | 每本作品的最新指标、身份、费用汇总和关联记录 | 选书、查看最新情况 |
| 每日数据 | 每个平台作品每天一条真实采样，含来源、采样时刻和缺失原因 | 查某一天的数值，导出分析 |
| 营销服务明细 | 每笔电子书营销的服务日期、内容、数量、费用、留档 | 核对投放与费用 |
| 榜单快照 | 每日每榜的名次；同一本书在不同榜上各留一条 | 查上下榜、历史名次 |
| 通知事件 | 事件、接收人、原生工作流状态 | 排查漏发、重复与失败 |
| 运行日志 | 来源任务的执行情况、时间和缺口 | 判断今天采集是否完整 |
| 规则配置 | 阈值、收件边界、暂停项与业务口径 | 管理监测规则 |

微信读书项目、番茄小说项目、仅榜单样本都是**项目总表的视图**，不是复制的表。微信／番茄每日指标也是每日数据的筛选视图。修改同一记录，会反映在其他包含它的视图中。

通知事件、运行日志、规则配置和工作流收在“系统后台（日常无需打开）”。唯一活动电脑已于2026-11-06启用番茄出版飙升榜采集和快照同步，每次须完整100名。已核实ID的营销作品按相邻两天完整采样的差异提醒上下榜，正文标明实际采样区间，并归入每日上榜／下榜汇总。首次或缺日不发，缺失快照不表示当天无人上榜；下榜也不代表作品下架。

## 选书和折线图

2026-11-10起，直接在**运营趋势看板**顶部使用个人切片器，不再修改项目记录来选书。

1. 在**选择作品**中搜索书名并多选，建议每个平台同时比较2–5本。
2. **统计日期**默认过去30天，可选择自定义日期范围。
3. 六张图使用同一组筛选，微信、番茄分别展示；缺失和未开分保持空值。
4. **一键清空选择（重新打开）**打开一个新的看板页面，选书清空、日期恢复默认30天。原页面可关闭；不修改数据，也不清空其他访问者的选择。
5. 清空选书表示不限制作品；数据多时应重新选书，而不是解读全量叠加曲线。

可阅读权限即可使用切片器，无需给使用者编辑原始数据的权限。筛选只在当前访问生效，刷新后清除；多人可同时用各自条件分析。已验证两个独立页面分别选书、互不覆盖及按钮重开后的重置；没有代登录八个成员账号进行并发验收。

旧的加入趋势对比、趋势起始/结束日期和趋势纳入公式保留兼容，但六张图不再依赖它们。不要重跑历史初始化脚本恢复共享选择模式。

已取消示例作品的固定纵轴上下限，防止新选作品超出边界后被裁切。当前采用飞书默认范围；推荐值仍可能从0开始，不能宣称已实现按最小值紧密自动缩放。

切片器官方说明当前最多获取5000条符合条件的记录。当前日表低于该值；后续增长超过此限制时需检查选项覆盖并调整选书数据源，不能把找不到选项当作作品不存在。

图例包含书名、作者和作品唯一键，用于区分同名书及版本。每日期每作品只有一个数值，图表用MAX取该值，不将人数跨书累加。

## 查每日明细

打开 **每日数据 → 微信每日指标／番茄每日指标**，按书名或关联项目筛选，再筛数据日期。项目总表的 **每日记录** 关联也可以进入该书的历史记录。

每日数据的“数据日期”是采样所在自然日；“采集时间”是实际采样时刻。已错过的历史数据不会补造，未开分或未采到的值留空。系统开始积累不足 30 天时，图上只会有实际记录的几天。

## 用指标判断变化

- 微信今日阅读：当天采样时平台显示的今日人数，不是全天最终值。不同天取样时刻差异很大时，应结合采集时间判断，不能直接解释成运营带来的涨跌。
- 点评人数：截至采样时的总人数。两天之差是净变化，可能包含新增、删除及平台修正；不等于新增书评篇数。
- 推荐值：平台展示百分数。未开分留空，不按 0 分画图。
- 番茄累计阅读：仅取明确“人读过”。例如 60.2 万是平台约数，应结合精度说明，不把显示数的差当成精确新增读者。
- 有缺失日期时，不把相邻有效点之间的线视为每天都成功采样。
- 营销效果：把服务日期与人数、费用放在同一观察期对照趋势；趋势相关不能单独证明投放因果效果。

## 榜单样本

“当前榜单”为单选。同书同时出现在多个榜时，使用组合标签（例如“出版飙升＋出版新书”），完整保留归属；“榜单核验日期”说明该结论来自哪一天。仅四榜各有唯一 1–50 名完整快照时更新；读取失败不改成未上榜。离榜作品会按原追踪期继续记录。

## 三家版权方新上架监测

目标范围是读客、果麦、微信读书出品。2026-11-05用户进一步确认，以版权方“最近上架”列表为来源，只统计新进入的作品。首次完整读取建立基线；之后新出现的官方作品ID从发现当天连续追踪30天。已有作品的连载更新、排序变化、改名、退出再进入都不算新增，也不重新起算。作品离开列表后继续追踪满30天。历史每日指标不补造。它独立于 Top50 新书榜。

每日10点任务现已读取三家完整最近上架列表并比较永久ID基线。新进入作品和30日指标同步到现有项目总表、每日数据。“首次进入最近上架日”记录实际发现日期，保留独立追踪截止日，和营销起点区分。来源失败时显示失败并保留基线，不能报告零本新增。

在项目总表选择“版权方新进入作品”视图，点“每日记录”查看逐日明细；直接在“运营趋势看板”的“选择作品”切片器中选书，可以比较推荐值、点评和今日阅读。今天基线建立后尚无新增时，此视图为空是正常结果。未开分数值留空，累计阅读人数口径仍待核实，不用今日阅读累加代替。

2026-11-05核验进展：果麦“本月重磅”进入后的页面标题是“最近上架”，每本显示“上架于”。其中8本可见作品的时间均与官方网页 `reader.bookInfo.onTime` 换算结果匹配到分钟。采集程序已保留原始时间戳及北京时间 `platform_listing_time`，与出版时间分开；缺失时留空。该字段尚不能证明是作品首次上架还是重新上架。

最近上架列表并非严格按日期倒序，不能遇到旧日期即停止。已通过用户扫码授权调用三家版权方书目接口，逐次核对返回总数与唯一ID；果麦前8本与截图顺序一致。脚本和边界见[最近上架来源](RECENT_RELEASE_SOURCE.md)。微信读书出品列表含连载更新，列表时间不能直接当作上架时间；已见ID更新不计新增。会话过期时需要重新登录，本模块不扩大发送通知范围。

# 电子书运营半月报 PRD

本模板沿用 2026 年 11 月首期的飞书阅读页、交互版 HTML 和图文版 PDF。运营人员可以看磨铁作品与全榜的差异，编辑可以按题材、二级标签和版权方了解市场，营销人员可以按服务日期核对投入和作品同期变化。三个版本共用一期数据和结论。

## 一、期次和观察范围

| 项目 | 取数约定 |
| --- | --- |
| 日期 | 按北京时间，首期为 2026 年 11 月 1–20 日。常规上半月为 1–15 日，下半月为 16–30 日，遇二月截至实际月末。按当前约定，31 日不纳入常规下半月。 |
| 首期衔接 | 首期和紧随其后的 11 月 16–30 日有五天重叠。跨期比较注明重叠日期。汇算全月时从按日事实重新去重。 |
| 榜单 | 微信读书出版飙升、出版新书、女生小说飙升、女生小说新书各取前 50 名。番茄小说出版飙升取前 100 名。每榜逐日验证名次连续、官方作品 ID 唯一。 |
| 有效观察 | 分平台写明本期实际首末采样日、完整榜单天数和中间缺日。使用已有的真实采样。未采到的日期保留空缺，跨缺日的名次只描述两个已观察到的位置。 |
| 作品与服务 | 仅计已核实的电子书。单平台以官方作品 ID 识别，跨榜按作品归并，跨平台按已核实的同一作品关系归并。缺身份或版权证据的条目单列，保留平台原文。 |

## 二、首页的四个数字

首页标题为「磨铁本期数据概览」。两组指标分别回答“哪些书上过榜”和“本期对哪些书花了营销费用”。按下表排成两组，组下分别说明分平台结果。

| 首页分组 | 指标 | 统计规则 |
| --- | --- | --- |
| 五榜上榜作品 | 自签约作品上榜数 | 从已核实的电子书营销书目识别自签约作品，取其中本期进过任一榜的作品。历史进入营销书目的作品仍可计入上榜数。 |
| 五榜上榜作品 | 其他磨铁版权作品上榜数 | 从各榜的平台版权署名及已确认别名识别磨铁版权，剔除已计入自签的同一作品，再跨榜、跨平台去重。 |
| 本期营销 | 本期营销作品数 | 按**服务日期**筛选有效的电子书营销服务，再按作品去重。曾经营销但本期无服务的作品不计入。一部作品本期多笔服务计一部。 |
| 本期营销 | 本期营销花费 | 汇总本期符合项目范围、可以归属的原表服务费。按服务记录去重，依源表金额统计。待分摊、待核金额单列。已有有效服务的作品可计入作品数，即使这笔金额仍待分摊。 |

跨平台分项同时列出重合作品数，合计使用去重结果。需要说明上榜与营销的交集时，用一句完整的话指明分母和期间，例如“本期开展营销的作品中，有〈数量〉部在本期五榜出现”。读者可在折叠明细里核对这四个数字。

## 三、正文结构

| 章节 | 本期要回答的问题 | 优先呈现 |
| --- | --- | --- |
| 1　磨铁本期数据概览 | 本期有多少自签和其他磨铁版权作品上榜？哪些平台发生了营销投入？ | 两组四项数字、分平台上榜和营销金额、跨平台重合说明 |
| 2　磨铁自签约作品 | 哪些书进过前十、持续多久？与同日同榜、同二级标签的其他作品相比，阅读表现如何？ | 逐本最佳名次与上榜日数，代表作的名次或今日阅读走势，同类参照。榜外作品有可比较的读数时可单列 |
| 3　其他磨铁版权作品 | 哪些作品撑起各榜表现，是否跨平台出现？ | 分平台作品数、前十作品和代表作，保留版权原署名和归并依据 |
| 4　微信四榜对照 | 相同名次段在四榜各有多少今日阅读？哪个榜前十与中段差别最大？ | 同单位的名次段对照图和各日中位数，写明这种差别出现了几天 |
| 5–8　微信四个榜各一章 | 每个榜哪些题材和二级标签作品多、读者多？哪些版权方上榜多、阅读集中？结论由多本还是单本带动？ | 分类和标签对照、版权方按作品数和阅读的两种排序、代表作及其贡献 |
| 9　番茄出版飙升榜 | 哪些题材、标签、版权方反复进入前十？不同名次段的作品累计读过人数如何？ | 上榜数和进过前十数的对照图，累计阅读图标注约数，单列版权待核 |
| 10　三家版权方上新 | 读客、果麦、微信读书出品分别有哪些首次进入“最近上架”的书？同批作品随上架观察天数怎样变化？ | 上新数量、题材分布、同批书的今日阅读及累计点评趋势、代表作 |
| 11　本期营销 | 本期在哪个平台、哪些书上花了多少钱？服务前后阅读、点评或名次怎样变化？ | 平台金额对照、服务日标记的作品走势、各笔服务及待分摊明细 |
| 12　下期编辑选题与约稿建议 | 哪些题材值得编辑对读或约稿？参照哪部作品、读稿时具体看什么？ | 每条建议写出本期事实、参照书、可执行的读稿或约稿动作。单本拉高整个题材时明确其局限 |

前十一章只陈述可以回查的数据和比较结果。一般榜单章节以整个榜为主体，磨铁作品明显领先或对全榜结论有实质影响时再点名。编辑建议集中在最后一章，避免把一次观察写成市场定论。

## 四、读数与比较方法

- **微信名次与今日阅读。** 默认分第 1–10、11–30、31–50 名。每榜每天分别计算各段今日阅读中位数，再统计两段都可比较的天数和高低关系。跨日合计“今日阅读”时标为逐日读数合计，同一读者可能在多天出现。
- **题材、二级标签和版权方。** 每组给出上榜作品数、进过前十的作品数，以及微信的今日阅读表现。区分按书计的数量、按“作品在某天”统计的阅读分布和阅读合计占比。以单本占该组阅读的比例说明集中度。版权方按榜单署名和已确认的别名统计。归入磨铁自签书目的作品仍保留平台原署名。
- **统计明细。** 展开后可查有效作品数、观察天数、有效读数、均值、中位数、样本方差及均值的 95% 置信区间。按首期方法以连续三日为一组重抽日期，完整保留同一天的作品，重复 4,000 次。可比日期少于五天、作品少于两部，或缺日使连续窗口无法成立时，置信区间留空并注明原因。正文用人数、差距和出现频次表达结果。
- **平台指标。** 微信使用明确标为“今日阅读”的读数。推荐值未开分时，显示“未开分”并保留空数值。番茄累计阅读只取平台明确标为“人读过”的数据，保留约数及上下界。番茄可另分第 51–100 名。两平台的这两项指标各画各的图。
- **竞品新书。** 以完整“最近上架”列表建立初始基线，之后首次进入的官方 ID 进入观察。D0 为首次观察到新进入当日，持续到 D29，保留可核实的实际上架时间。连载更新、重入和改名沿用原记录。比较 D0 与 D7 等节点用同一批有前后读数的作品，标出可比本数。短期尚未到达的节点留空。累计点评的净增由两个实测值相减。
- **营销变化。** 服务日为中心，分别取前三天与后三天的真实采样，注明有效天数。今日阅读可比较前后中位数。累计点评比较前窗最后与后窗最后一次读数，写明日期。榜单名次、推荐值及番茄累计读过人数另列，阅读约数的变化保留边界。多次服务窗口相交时，标出重叠，避免重复加总。业务解释限于同期变化，营销带来的净增需要独立证据。
- **费用与单位。** 每笔保留平台、服务日期、作品、服务内容、原始数量及单位、服务费和留档。原表“服务费”为金额依据，单价供参考。推书帖条数与邀评人数分别列示。源行更正后按原位记录复核，已排除的服务保持原审计记录。

## 五、阅读页与文件

1. **飞书主入口。** 在项目多维表格的「运营半月报」目录中，每期使用带起止日期的原生图文页。读者点期次即可看到章节目录、正文和图表。页首并列提供「交互版 HTML」和「图文版 PDF」两张附件卡，并注明 HTML 下载后用浏览器打开。如果部署环境只能使用数据表，读者视图只设「时间」和「半月报」两列，后一列放两个附件。逐行存档归入系统后台。
2. **图文版式。** 延续首期 izna 版的深海军蓝标题、白底和蓝色图表。每节用直白的小标题、带单位和时间范围的图、可核对的作品例子。趋势用折线，类别与版权方比较用条形，阅读与名次分图标注。颜色之外同时提供系列名和数值，使图表在桌面、手机及打印页均能读清。
3. **交互与打印。** HTML 默认折叠数据明细，支持按书名、榜单、题材或版权方查找，再展开单部作品的逐日记录。搜索、清空、翻页均能使用。PDF 使用相同的期次、四项数字、图表和结论，提供适合 A4 阅读的静态版，图注和关键解释在纸面上可见。

## 六、发布与验收

| 验收对象 | 可直接检查的结果 |
| --- | --- |
| 数据 | 将首页四项数字分别与去重书单、服务逐笔核对。复核跨平台交集、未归属费用和各榜实际覆盖。图上的数值和正文的结论均能按来源复算，代表作的名次、日期和阅读数能回到同一条来源。 |
| 三个版本 | 飞书正文、HTML 和 PDF 的期次、统计和图注一致。通过飞书实际打开本期阅读页，回读文图和两个附件，将下载文件与发布原件核对。 |
| 阅读体验 | 首屏能区分上榜与营销，目录能直达任一榜单。用一本书、一个二级标签和一个版权方验证展开、筛选和清空，检查手机宽度及 PDF 分页。 |
| 通知 | 负责人明确要求通知后，通过项目原生工作流向当时批准的正式日报名单发一条。以本期期次独立去重，标题含月日范围，正文附本期阅读页直达链接并说明互动版和 PDF。核对实际名单和工作流“已发送”状态，保留与日常两条日报各自独立的回执。 |
| 异常 | 会影响结论的来源、作品归并或费用尚待核实时，先向负责人说明影响范围。页面、附件、收件名单核验未通过时暂停通知。投递结果未知时先对账。 |

### 通知文案模板

> 《〈月〉月〈起始日〉日至〈结束日〉日电子书运营半月报》
>
> 〈本期飞书阅读页直达链接〉
>
> 本期涵盖磨铁作品的上榜与营销表现、微信读书和番茄小说五个榜单，以及三家版权方的新书表现。页面顶部可下载互动版和 PDF。互动版用浏览器打开，可按书名、榜单、题材或版权方查明细。PDF 适合阅读和打印。

收到具体期次和发布授权后复用这份模板。GitHub 保存需求、版式和统计方法。实际公司报告、费用、作品明细、业务链接、账号和投递回执保存在项目的私有空间。

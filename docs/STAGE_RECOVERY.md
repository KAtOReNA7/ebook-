# 分阶段证据保存与故障恢复

2026-11-11新增，协议v8。每日入口仍为 `python scripts/daily_run.py --run-kind scheduled`。

## 保存时机

1. 全局锁内恢复完整共享检查点。
2. 每个模块第一次业务写入之前，将当前原始观察、同步计划和未完成guard保存至私有系统运行状态，并完整校验哈希和回读。失败则不执行该次业务写入。
3. 模块完成后再次保存状态，包括失败或待核状态；发布核验及通知也分别保存。不改变通知准入、收件人和日期去重。
4. 最后仍提交完整检查点、回读并释放锁。阶段日志随后被新完整检查点取代。

阶段日志只存相对本轮完整检查点的差异，采用双槽和最后切换指针。未变更的旧历史证据不重复上传；阶段写入失败不能替换此前已验证指针。阶段表数据和账号ID仍仅留在私有Base，凭据与会话不上传。

## 中断后怎么处理

从另一台已授权电脑读取并导出证据：

```powershell
python tools/inspect_interrupted_stage.py --export-evidence
```

它输出最后保存模块、阶段、锁归属是否匹配和未完成guard，将校验通过的完整证据导出到新的私有receipts目录。不会覆盖当前缓存、释放锁、写业务表或发送消息；不需要原电脑开机或用户搬运文件。默认不加参数只检查。

若中断发生在写入期间，必须用保存的计划和飞书完整回读判断哪些写入实际完成，之后才能受控恢复；不能删除guard、按超时抢锁或直接重跑。阶段记录仍属当前完整检查点且未对账时，新入口拒绝执行。代码不会把阶段的“completed”当作整个任务完成，也不会把失败的阶段存储报告为成功。

## 验收边界

- 模拟测试涵盖：写入前保存失败则零业务写入；另一空目录恢复同一实际采样与未知guard；不完整上传保持旧指针；数据损坏、父检查点不匹配和错误租约拒绝恢复；重复保存无写入及双槽有界。
- 真实验证只写系统状态，不故意中断公司数据写入、不发测试通知。实机断电故障恢复不能由模拟测试替代。
- 采集中尚未保存的部分仍可能丢失，恢复后只能记录重新采集的实际时间；不伪造原时刻。锁或写入结果未知时仍需先对账，不承诺无限制自动接管。

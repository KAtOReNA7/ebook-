# 每日监测执行效率与故障接续优化任务

状态：待实施，尚未性能验收。问题依据：[2026-11-15运行复盘](RUN_REVIEW_20261115.md)。执行说明：[周中电脑接续](WEEKDAY_OPTIMIZATION_HANDOFF.md)。

## 目标

优化现有流程，减少无效工作和故障后的重复流程。优先选择最小必要改动，不先建设新框架或引入新服务。

正常日任务争取60分钟内完成；最后一项必要来源采齐后，比较、发布和共享提交争取15分钟内完成。以实际墙钟时间验收；未达目标必须列明阶段耗时和剩余瓶颈。不能以后台任务启动或进程退出码0当作完成。

## 执行顺序

1. 利用可用日志量化采集、业务读写、共享状态读写、锁检查、重试及恢复的耗时、调用次数和字节量。计时应区分正常运行与故障恢复，重叠时间不能简单求和。原电脑拿不到11月15日本机日志时，以脱敏复盘作为初始依据，先用合成数据建立可复现基准；不得要求用户手动搬运每日状态包才开始工作。
2. 首先减少共享状态开销。按键获取HEAD、仅读取有效槽及必要块，避免为一个指针扫描整张状态表。按变化保存，无变化模块不反复上传；核对固定基线增量、双槽、历史证据保留与重复读回的成本。归档与日常工作集须保持原字节、哈希及跨电脑可恢复性；不未经核查删除历史证据。
3. 从失败步骤接续。已完成且证据有效的来源复用；单请求失败仅补对应作品；共享保存失败只恢复保存；通知已创建只核对状态。正式受控接续必须核验原租约、存活执行、远端阶段、写入计划及回读，不能按超时抢锁或直接改完成标记。
4. 调整采集与检查顺序。评估网页读取的有界并发、限速、退避和有限重试。避免dry-run与正式运行重复全量采集：同日合格真实观察可经明确的受控入口复用，不能信任未提交本机完成标记。只读失败与未知写入分开处理；不自动重试未知POST/PATCH。
5. 合并无效重复检查。保留发布前新鲜、独立的完整业务回读及必要写后核验；没有新变化时消除重复扫描。不得缓存过期的锁归属或收件名单来减少调用。
6. 分开发修复与生产执行。核查本机实际能力，补齐复盘中仍未提交的失败请求处理及发布门禁；先模拟验证再启动真实运行。运行中的进程不靠改源码热更新。摘要直接报告当前阶段、耗时、故障原因及下一步，不依赖人工高频查询。

## 必须保持

- 保留本机私有配置、凭据、未提交修改及原始证据；不reset、clean、强推或恢复旧stash。
- 共享进度为权威，全局互斥、跨电脑自动恢复和日数据/日报去重有效。
- 正式范围仅电子书；五榜完整、费用、业务比较、版权和独立回读全部通过，才发布两条日报。
- 使用恢复后共享runtime批准名单，尊重发布暂停状态；不扩大名单、不发测试或直接IM、不回放历史通知。
- 只用现有网页采集，不启App/ADB/模拟器，不猜ID、不造零、不改采样时间、不新建基线。
- 共享协议不降级。若改动不向后兼容，必须升级版本并使旧写入端明确拒绝，不静默丢弃状态。
- 默认复用现有环境。新增存储或服务必须说明必要性及迁移/回退方案，不能把未经验证的架构迁移混进当天采集。

## 验证与交付

- 给出改前/改后的阶段耗时、调用数和传输字节量；注明数据规模、网络条件和测量方法。
- 模拟覆盖：重复运行不重复业务写入；失败仅补失败项；网络读恢复有上限；未知写入先对账；错误租约拒绝；新电脑恢复保留原字节及通知去重；发送后故障不重发；发布失败两条均停发。
- 为状态查询及无变化复用建立调用数量回归检查，防止以后重新退化成全表扫描。
- 在下一次获授权的正常日任务验证完整流程及实际耗时。优化开发本身不自动触发生产日报；不得为性能验收重跑11月15日或补发历史。
- 发布测试过的最小必要代码、变更说明、运行命令及回退办法；不提交私有数据。回退不得恢复旧业务状态或降级共享检查点。
- 最终列明已解决/未解决问题及真实运行验收结果。模拟通过不代替现场验收，未达到60/15分钟目标不得宣称达标。

建议首先审查：`scripts/shared_runtime.py`、`scripts/stage_checkpoint.py`、`scripts/feishu_io.py`、`scripts/daily_run.py`。随后按测量结果处理采集并发及来源补采。Windows10点任务失败另列调度缺陷，本次手动完成不能作为自动触发证据，也不通过新增第二个日程掩盖失败。

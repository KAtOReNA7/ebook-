## 2. 固定恢复清单

统一只读命令：

```powershell
python tools/inspect_interrupted_stage.py --export-evidence --reconcile
```

工具完整读取远端检查点、阶段证据、原租约及所有受影响业务表，输出私有`recovery-plan.json`。每条计划写入分类为已确认、未观察到、字段冲突或重复键；列出已完成阶段、尚无完成证据的阶段、未决保护和下一步。读取结束再次核对HEAD、原锁及阶段日志，没有改变才保留有效结果。

“未观察到”不等于确定未执行，可能是读取延迟或未知写入。工具绝不据此重发请求，不删除guard、不释放或抢占锁、不发送通知。只有原Windows主机和checkout、原进程及采集子进程已停止、原租约和当日证据一致、全部计划回读匹配、无未决保护，才建议现有`--resume-interrupted`入口；执行入口仍会独立重做核验，不信任旧报告作为写入授权。已完成来源不重做，发布前独立回读保留。

## 3. 微信逐作品采样进度

每本成功的详情和明确搜索阅读指标分别保存原子JSON记录，包含官方ID、观察时刻、原文路径、哈希和解析结果；失败或未知阅读值不标为成功。文件位于私有`runs/<日期>/raw-weread-*/sample-*.json`，随既有阶段证据自动共享。

整批快照尚未冻结时发生采集异常，父进程保存失败阶段证据；受控恢复后，采集器只复用远端权威恢复清单中当日、逐字节哈希匹配的记录。重新解析原文核对ID和指标，跨电脑只重定位证据路径，保留实际观察时间。详情成功、阅读失败时只补阅读；最终快照写出失败时可复用已保存的两个部分。新采样使用独立目录，不覆盖旧原文。榜单仍重新完整采集，榜内阅读以当前榜单观察为准。

只有本机文件、旧日数据、错误ID、来源或字段不一致、损坏文件均不能授权复用。未提交的本机数据仍会按现有协议隔离；若电脑突然断电且失败阶段未上传，不能承诺这些未提交观察可跨机恢复。已冻结或已同步的快照不会被本功能自动覆盖，仍遵守原补采与未知写入核验流程。

`sampling_progress`进入快照和微信模块摘要，记录详情/阅读复用数、保存数和拒绝数。不缓存章节或用户登录信息。

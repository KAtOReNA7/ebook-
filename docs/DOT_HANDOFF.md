## 目标端必须先证明的能力

1. 可在原电脑关闭时，每天北京时间 10:00 启动现有 Python 入口。
2. 可以运行受控版本的 Python 与 `@larksuite/cli`，使用 `--as user`。
3. 可以跨任务保存私有配置、永久作品注册表、费用比较基线、每日采样、
   通知去重记录、变更保护状态及回执，并能备份、恢复及完整校验。
4. 可以正常访问腾讯费用来源、微信读书、番茄网页和飞书。
5. 飞书和微信读书需要目标端自己的正常登录授权及续期方式；不复制
   Windows 凭据库、Cookie、Token 或 `.codex` 目录。

本机继续使用 Windows DPAPI。目标 Linux 可选择新增 `.aesgcm` 存储和独立
扫码授权，详见下述准备步骤。加密单元测试通过不代表目标实际登录成功；
未取得目标完整采集回执前，版权方模块不能标为已迁移。

## 目标下一步：只验证运行能力

先核对工作区，安全更新到本次经过测试的提交；保留已有文件，不 reset/clean。
运行以下命令，不需要私有状态包、不触及 Base：

```sh
python -m pip install -r requirements-dot.txt
npm install -g @larksuite/cli@1.0.87
lark-cli --version
python -m unittest discover -s tests -t .
python tools/runtime_probe.py network
python tools/runtime_probe.py begin --marker /实际持久目录/ebook-runtime-probe.json
```

记录最后命令输出的绝对路径、`expected_sha256`、创建时间及当前 Git 提交。
在 **Dot 的另一轮定时任务** 中，用完全相同路径与原始哈希执行：

```sh
python /实际代码目录/tools/runtime_probe.py check \
  --marker /实际持久目录/ebook-runtime-probe.json \
  --expected-sha256 上一步实际返回的哈希
```

该试验定时任务只检查标记并回报结果，不运行 `daily_run`，不恢复状态、
不调用飞书、不发送业务通知。需要保留平台调度的计划时刻、实际触发时刻、
任务标识和命令结果，用户本机离线时也应执行。缺文件必须报告失败，
不能重新 `begin` 后当作验证成功。同一进程立即运行两次不是跨任务证据。
即使一次定时检查成功，也仍须确认平台承诺的长期保存与备份位置。

`network` 仅检查公开主机是否返回 HTTP 响应。401/403/404 等响应仅证明
连通，不代表认证成功或可完整采集；随后必须在恢复私有状态并登录后
读取真实来源。工具不会把探测通过标为迁移成功。

## Linux 的独立登录与会话续期

新适配使用 PyCA `cryptography` AES-256-GCM，随机12字节 nonce 和版本化
认证头。参考 [PyCA AESGCM 文档](https://cryptography.io/en/stable/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM)。
密钥和密文分别保存；密钥必须在代码目录与状态包之外，POSIX 文件仅属主
可读写。此方式依赖目标账户和存储访问控制，不等于 Windows 系统密钥库。
不得将密钥、Token 或加密会话粘贴进聊天、提交 Git 或打进状态交接包。
目标持久目录未确定前先不要生成正式登录。

```sh
# 以下路径必须替换成经跨任务验证的私人持久位置。
export EBOOK_WEREAD_KEY_FILE=/私人凭据目录/weread.key
python tools/weread_login.py init-key
python tools/weread_login.py login --session-file /私人凭据目录/session.aesgcm
```

登录命令输出临时 SVG 二维码路径，由 Dot 展示给用户，用微信扫码并确认。
成功后只打印状态，授权信息直接加密；拒绝、超时或失败不建立会话。
默认等待240秒。二维码在结束后删除；使用新文件名重新授权，不覆盖旧会话。
绝不能把本机 DPAPI 解密后传给 Dot。新设备登录可能影响旧会话，宜在
持久性和调度准备通过后、切换前再做，并核实本机任务状态。

仅在目标私有 `config/publisher-newbooks.json` 的 `session_file` 改为新
`.aesgcm` 绝对路径。原 Windows 配置不动。定时任务必须使用相同运行账户、
代码版本、依赖及 `EBOOK_WEREAD_KEY_FILE`；环境变量只含文件路径。
续期沿用同一加密后端，身份不匹配、密文损坏、缺密钥时拒绝覆盖原文件。
飞书授权另按 `lark-cli auth --help` 的当前流程完成，用 `--as user` 核实身份。
不要在授权成功前运行业务写入，也不要通过测试消息验证登录。

## 交接内容

- 代码：记录经过测试的 Git 提交；目标固定该版本，不在定时任务里自动拉最新代码。
- 私有配置：现用 Base、字段、身份映射、电子书证据、收件边界、通知汇总配置。
- 状态：所有仍被读取的注册表、当前比较基线、完整采样、未完成保护文件和回执。
- 操作说明：当前私有 `RUNBOOK.md` 和最新用户更正。历史说明不得覆盖现用政策。
- 登录：目标端重新授权，不放进代码仓库或普通交接压缩包。

`tools/handoff.py` 可导出校验私有状态；该包不能公开上传，也不是凭据迁移工具。
现有工具跳过公共政策文件。尤其要单独核对活动端已授权的番茄榜单配置，
不能让仓库中默认暂停配置静默覆盖实际运行政策。费用源证据必须与引用的
SHA256 一致；不能为减小包体而移除仍被活动配置引用的文件。

## 试跑与切换

1. 核对本地工作区和未知变更保护状态；冻结一份带时间及校验清单的交接快照。
2. 目标端恢复代码和私有状态，通知关闭；运行 `python tools/doctor.py`。
3. 目标端完成登录后只运行 `python scripts/daily_run.py --run-kind local --dry-run`。
   `--shadow` 仍会写业务数据，不能代替 `--dry-run`。
4. 单独验证全量新来源采集，避免当天已完成状态复用历史快照掩盖目标端网络问题。
   微信四榜各唯一 1–50 名；番茄出版飙升榜完整 100 名；版权方最近上架
   返回总数和唯一 ID 一致；腾讯全表完整读取。已知待核作品继续单列。
5. 只读核对七张飞书表、费用合计、关联及事件去重；校验原永久注册表未被重建。
6. 确认目标调度可以独立启动后，停用原定时任务并确认没有本地写入进程。
   最后同步增量状态，验证哈希，再启用目标定时任务。切换期间始终只有一个写入端。
7. 首次目标写入完成后完整回读，并实际验证一次原电脑离线时的定时执行。
   不补造历史采样，不重放旧通知；调试通知始终仅本人。

若目标试跑失败，继续保留原运行端。若已切换后失败，先停止目标调度、
核对飞书及最新状态，再决定恢复原端；不能两端同时重试。

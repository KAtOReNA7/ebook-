# 阅读平台运营监测

以飞书多维表格为中心，整理腾讯营销费用、采集微信读书与番茄小说的作品数据，并通过飞书原生工作流通知。Python 采集程序是主体；浏览器用于核实来源，优先内置浏览器，不使用 Chrome。

本项目仍在调试。用户明确“正式通过”之前，通知只能给已核实的项目所有者。番茄出版飙升榜仍由用户暂停，仅保留入口，不启动 App、应用宝或安卓调试。

## 已有功能

| 模块 | 行为 |
| --- | --- |
| 腾讯费用表 | 完整读取源表，逐行保留日期、服务、人数、金额、留档及指纹；只接纳已确认电子书服务；源修改、删除与身份变更先核对 |
| 项目总表 | 关联营销服务、每日数据和榜单；保留真实作品 ID、入表起点、版权与两级分类及资料来源 |
| 微信读书 | 每日采集四个 Top50 榜单和作品指标；完整 1–50 名才比较上下榜；下榜继续追踪至满 30 天 |
| 番茄网页 | 采集已核实作品资料、点评、书评及明确“人读过”的累计阅读；保留约数边界，不以在读/飙升值代替 |
| 通知 | 推荐值跨越 90%、相关上下榜、新营销条目、费用变化及番茄阅读里程碑；统一事件表去重、原生工作流发送 |
| 验证 | 操作系统锁、冻结观察、未知写入保护、完整回读、费用核对、通知健康检查 |

每日计划在北京时间 **10:00** 启动，记录实际采样时间。未开分保留空数值并注明原因；来源缺失不能自动填零。番茄 7/14/30 天窗口从首次进入营销项目当天起算。

截至 2026-11-04，番茄营销作品的作者和作品分类已补齐，34/97 本接通番茄官方 ID 与采样；其余 63 本仍待核实番茄 ID，作品级参考资料与番茄原生指标有明确区分。基础资料齐全不等于全部动态指标接通。当前数值只是交接时的状态，最新结果须在运行后回读确认。

## 在其他电脑继续开发

Python **3.11 或更新版本**；运行及单元测试使用标准库。当前本机验证版本为 Python 3.14、飞书 CLI 1.0.87。

```powershell
git clone https://github.com/KAtOReNA7/ebook-.git
cd ebook-
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m unittest discover -s tests -t .
```

以上步骤无需飞书登录，也不会读写线上表格。macOS/Linux 使用 `source .venv/bin/activate`；日常开发优先运行模拟外部服务的单元测试。

**接续现有系统还需要私下传递本地状态包，并在新电脑重新登录飞书。** 公开 Git 仓库不包含费用数据、现场留档、账号登录、真实 Base 清单、作品身份映射或通知去重状态。不能用示例配置创建全新基线后直接对现有 Base 写入。

完整步骤见 [跨电脑交接](docs/HANDOFF.md)。开发入口与维护约束见 [开发说明](docs/DEVELOPMENT.md)。原电脑私有 `RUNBOOK.md` 是现场记录，随私有状态包传递。

日常选书、折线对比和各表用途见 [运营使用说明](docs/OPERATIONS.md)。原生运营趋势看板由“加入趋势对比”与可选起止日期驱动；三家版权方新上架监测的来源核验仍未完成，不能把现有 Top50 采集视为该范围已接通。

## 目录

```text
scripts/                 采集、同步、去重、受控身份归并与验证
tests/                   单元测试，外部服务使用模拟对象
config/*.example.json    不含真实账号/数据的配置示例
config/                  可公开的范围与指标口径；真实部署配置不入库
tools/doctor.py          本地只读配置与证据依赖检查
tools/handoff.py         私有状态包导出、校验、恢复
docs/                    开发与交接说明
.github/workflows/       仅运行测试，不部署或采集线上数据
```

历史一次性验收、旧系统激活和特定源行修复脚本留在原电脑，不作为公开项目入口。已停用的旧测试系统不得恢复、迁移或执行。

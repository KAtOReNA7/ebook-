# 阅读平台运营监测

项目每天读取腾讯电子书营销费用、微信读书与番茄小说的作品数据，写入飞书多维表格。任一使用当前代码并独立登录的电脑都可以运行同一个入口。程序先取得全局锁，再恢复私有 v9 共享检查点，同日按记录与通知键去重。[跨电脑运行与恢复](docs/SHARED_RUNTIME.md)

每日入口为 `python scripts/daily_run.py --run-kind scheduled`。网页采集使用项目现有 Python 程序。运营端在来源、费用、业务比较、当日独立回读、五榜版权和工作流名单全部核验后，通过原生工作流向共享配置批准的成员发布两条日报。任一项失败或发布暂停时，两条都停发。发生未知写入时先只读对账。[阶段恢复](docs/STAGE_RECOVERY.md) · [逐作品采样续接](docs/RUNTIME_RESUME_20261118.md)

## 已有功能

| 模块 | 行为 |
| --- | --- |
| 腾讯费用表 | 完整读取源表，逐行保留日期、服务、人数、金额、留档及指纹；只接纳已确认电子书服务；源修改、删除与身份变更先核对 |
| 项目总表 | 关联营销服务、每日数据和榜单；保留真实作品 ID、入表起点、版权与两级分类及资料来源 |
| 微信读书 | 每日采集四个 Top50 榜单和作品指标；完整 1–50 名才比较上下榜；下榜继续追踪至满 30 天 |
| 番茄网页 | 采集已核实作品资料、点评、书评及明确“人读过”的累计阅读；保留约数边界，不以在读/飙升值代替 |
| 版权方最近上架 | 完整读取读客、果麦、微信读书出品列表；基线后首次新ID追踪30天，采集推荐值、点评与今日阅读，同步现有项目和每日数据；累计阅读口径待核实 |
| 通知 | 每日两条：《年月日电子书明细》列营销变化及上/下榜、90%和里程碑等业务变化，营销无变化显示“无”；《年月日电子书汇总》分微信读书、番茄小说两部分。微信四榜列磨铁数量、版权方排名及作品名次，零磨铁榜单列版权方前五名；番茄完整出版飙升榜列磨铁上榜数量及作品名次，无则写“无”，不排版权方名次。无变化也发送日报；统一事件表去重、原生工作流发送 |
| 验证 | 操作系统锁、冻结观察、未知写入保护、完整回读、费用核对、通知健康检查 |

每日计划在北京时间 **10:00** 启动，记录实际采样时间。未开分保留空数值并注明原因；来源缺失不能自动填零。番茄 7/14/30 天窗口从首次进入营销项目当天起算。

制作电子书运营半月报时，期次、统计口径、章节版式、飞书阅读页和通知验收均见[半月报 PRD](docs/HALF_MONTH_REPORT_PRD.md)。

每次运行的实际覆盖见当日 `runs/<日期>/acceptance-summary.json` 和来源报告。作品资料、已核实的平台 ID 和当日实际采集的指标分别核对。

## 在其他电脑继续开发

Python **3.11 或更新版本**；现有 Windows 采集使用标准库。Linux/Dot 加密会话与扫码工具的可选依赖见 `requirements-dot.txt`。当前本机验证版本为 Python 3.14、飞书 CLI 1.0.87。

```powershell
git clone https://github.com/KAtOReNA7/ebook-.git
cd ebook-
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m unittest discover -s tests -t .
```

以上步骤无需飞书登录，也不会读写线上表格。macOS/Linux 使用 `source .venv/bin/activate`；日常开发优先运行模拟外部服务的单元测试。

**接续现有系统须一次性配置项目访问入口，并在新电脑独立登录；日常状态由私有飞书共享检查点自动恢复，无需手工传包。** 公开 Git 仓库不包含费用数据、现场留档、账号登录、真实 Base 清单、作品身份映射或通知去重状态。不能用示例配置创建全新基线后直接对现有 Base 写入。

完整步骤见 [跨电脑交接](docs/HANDOFF.md)。开发入口与维护约束见 [开发说明](docs/DEVELOPMENT.md)。原电脑私有 `RUNBOOK.md` 是现场记录，随私有状态包传递。

每日运行迁移到 Dot 的准备、独立登录、跨任务持久性检查和单写入端切换见
[Dot 交接](docs/DOT_HANDOFF.md)。当前仍由本机运行；代码适配不等于已完成迁移。

不依赖Codex或Dot的常开Windows运行端，以及其他电脑并行开发的安排，见
[Windows运行交接](docs/WINDOWS_RUNNER_HANDOFF.md)。可导出禁用的10点任务模板，
先验证dry-run、用户登录及实际调度；各电脑使用共享锁和检查点自动接续，无需每日状态包。

2026-11-05 已验证番茄出版飙升榜的独立只读采集路径，可获取官方返回的完整 100 本榜单。
运行方式和校验边界见 [出版飙升榜采集验证](docs/FANQIE_PUBLICATION_RISING.md)。2026-11-06，唯一活动电脑已按授权通过完整100名验证与dry-run，启用每日采集及飞书榜单快照同步；公共默认配置仍暂停。用户随后确认按相邻两天完整采样的差异提醒上下榜，正文注明实际采样区间，不推断平台精确更新时间。首次只建基线，不补发历史。
榜单接续和营销作品身份核验各有专门入口。[番茄榜单接续说明](docs/FANQIE_RISING_HANDOFF.md) · [番茄营销覆盖核验](docs/FANQIE_COVERAGE.md)

日常选书、折线对比和各表用途见 [运营使用说明](docs/OPERATIONS.md)。运营趋势看板使用[自定义只读组件](web/trend-plugin/README.md)，个人在页面内选书、筛日期和清空；纵轴随个人选择自动调整，旧项目勾选字段已隐藏。三家版权方最近上架已接入同一每日入口，使用“版权方新进入作品”视图；初始存量仅建基线，连载更新与重入不重置30日窗口。已授权会话认证失效时尝试官方续期；续期失败则冻结来源基线，重新登录后恢复。缺失指标留空；现有项目已获正式运行授权，缺失指标和待核作品仍如实披露。

## 目录

```text
scripts/                 采集、同步、去重、受控身份归并与验证
tests/                   单元测试，外部服务使用模拟对象
config/*.example.json    不含真实账号/数据的配置示例
config/                  可公开的范围与指标口径；真实部署配置不入库
tools/doctor.py          本地只读配置与证据依赖检查
tools/handoff.py         私有状态包导出、校验、恢复
docs/                    开发与交接说明
.github/workflows/       Python测试和趋势插件静态代码部署；不执行日采集
web/trend-plugin/        飞书看板插件源码；无业务数据、凭据或数据代理
```

历史一次性验收、旧系统激活和特定源行修复脚本留在原电脑，不作为公开项目入口。已停用的旧测试系统不得恢复、迁移或执行。

2026-11-11补强：每日各模块写入前、完成后增加私有增量证据保存；保存失败禁止业务写入，另一台电脑可直接核对已保存证据。见[分阶段恢复与周末验收](docs/STAGE_RECOVERY.md)。
